## Patch rules that affect this

- `Patchsu/patches/patches.meta.json` lists each patch's `needs`. The "Vanilla+" preset should only be patches that minimally affect gameplay/user interface and do not overcomplicate lazer.
- Reach 0002 state through game APIs instead: the active local profile is the API's `LocalUser`.
- 0500. 0501 and 0502, contain the replay toggles for their own mods inside `#if PATCHSU_REPLAY_MOD_TOGGLES`, which 0005 defines in
  `Directory.Build.props`. Build them both with and without 0005.
- Regenerate a patch by splicing only the files you changed (`tools/merge_sections.py`) against that patch's own base. Keep the
  disclaimer header **once per patch**.
- Before finishing:
  - apply the full stack plus the presets;
  - build with **0 warnings**;
  - run the tests in `Patchsu/work/*-tests` and `Patchsu/work/opt-tests`;
  - save patch backups in `Patchsu/work/old-patches/`;
  - check that no other session changed a patch significantly, if possible read last few sentences of thinking trace to see what Agent is doing and figure out if you can merge (compare with your backup before copying).

If user system is Linux
  - `/tmp` is a 16 GB tmpfs. Every scratch clone and build is about 0.8–2 GB, so delete them as you go. A full `/tmp` makes headless tests fail with misleading errors ("No space left on device").

## Working on a patch

- **Work clones**: `git clone --shared Patchsu/osu-lazer Patchsu/work/pNN`, apply the patch's base (its `needs`, in glob order),
  commit as the base, then commit your change. Regenerate with `{ cat header; git diff --binary HEAD~1 HEAD; }`. Patches without a
  header (0003, 0004) are just the diff. Keep each patch's header in a durable file (`work/old-patches/<id>-header.txt`), not only in a
  scratch directory.
- **Before overwriting a patch, diff the regenerated file against the current one.** The maintainer sometimes hand-edits patches
  (UI wording especially). Port any hunk you didn't make into the work clone first, or splice only your files with `merge_sections.py`.
- New files in a clone need `git add -N` (or `git add -A`) before `git diff`, or they're silently missing from the patch.
- The clones check `.cs` files out with **CRLF**. Scripted edits must match `\r\n`.
- `global.json` wants **SDK 10**. If the system `dotnet` is newer, run with `DOTNET_ROOT=$HOME/.dotnet PATH=$HOME/.dotnet:$PATH`
  (or wherever SDK 10 is). If none found, install it in `/work` folder and build with it, but keep it out of repository push
- Tests are copied into the clone's test projects (`osu.Game.Tests/Visual/Navigation`, `…/SongSelect`, `…/Gameplay`, `NonVisual`,
  `osu.Game.Rulesets.Osu.Tests`) and run with `dotnet test --filter`. They never go into the patches.
- Visual changes: check them on screen (a scratch `OsuGameBase`/`OsuGame` subclass + `Host.TakeScreenshotAsync`, with its own data
  directory that you delete afterwards), compare screenshots by pixels, and check light and coloured backgrounds too, not just black.

## Things the maintainer decided (don't "fix" them back)

- Settings → Patchsu: one `PatchSettingsSubsection` per patch that has settings, titled "Patch N. <≤3 words>". No info-only subsections.
- The product name is "Patchsu". The data subfolder is `patchsu-osu/` (2026-11-26; 0001 renames an old `osu-local/` on the first start, so never create `osu-local/` again). The `OSU_LOCAL_DISABLE` env var keeps its old name.
- **Every patch setting goes into `PatchsuSettings.json`** through `PatchsuSettings.Current` (0001), including song select UI state. Never add `OsuSetting` entries / game.ini values or a patch's own settings file. Use one section per patch, named after what the patch does (not its number), and pass `oldGameIniKey` / take over an old file once when moving an existing setting.
- JSON files stay indented and readable. Don't store values nobody needs (e.g. unfinished plays keep only non-zero statistics).
- Replay mod toggles (0005, and the toggles 0500/0501/0502 build in with it) must **never change a replay's result**: only what is seen and heard on REPLAY VIEW itself.

## Safety

- **Never touch the real osu! data folder** (`~/.local/share/osu`, `%APPDATA%\osu`) from tests or scratch apps. Use a separate data directory.
- `BeatmapManager.Import(new ImportTask(path))` **deletes the source file** after importing. Copy a user's `.osz` (or a repo test resource) to a scratch directory before importing it.
- Never build or install over the user's installed Patchsu (`~/.local/share/patchsu-app`, `%APPDATA%\patchsu-app`) unless asked; use `--prefix` into scratch.
- Don't push, publish releases or upload anything to GitHub unless the maintainer says so.
